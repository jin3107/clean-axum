# catemplate-rust

A full-stack project template: an Axum REST API organised as a clean architecture
workspace, PostgreSQL (Citus ready), and a React + Vite client.

Forked from [kigawas/clean-axum](https://github.com/kigawas/clean-axum) by
Weiliang Li, and extended with authentication, multi-tenancy, a web client and
project generation. See [License and credits](#license-and-credits).

## Features

- [Axum](https://github.com/tokio-rs/axum) REST API with
  [SeaORM](https://github.com/SeaQL/sea-orm) and migrations
- PostgreSQL; the database is created on first start when missing
- JWT access tokens, rotating refresh tokens, logout, Argon2 password hashing
- Roles and tenant isolation, with a schema that can be distributed by Citus
- Request logging, CORS, rate limiting on sign-in
- Swagger UI and Scalar, generated by [utoipa](https://github.com/juhaku/utoipa)
- React 19, TypeScript and Vite client skeleton in `client/`
- `cargo generate` template on the [`template`](../../tree/template) branch

## Requirements

| Tool | Notes |
|---|---|
| Rust (stable) | on Windows also the Visual Studio C++ build tools |
| PostgreSQL | a user that may create databases, or an existing database |
| Node.js 22.12 or newer | for the client; CI uses 24 |
| cargo-generate | to create projects from the template |
| Docker with Compose | optional, see [Docker](#docker) |

## Create a new project

Install the generator once:

```bash
cargo install cargo-generate --locked
```

Generate a project:

```bash
cargo generate --git https://github.com/jin3107/clean-axum.git --branch template --name my-app
```

To shorten the command, add this to `cargo-generate.toml` in your `CARGO_HOME`
folder (by default `~/.cargo`):

```toml
[favorites.catemplate-rust]
description = "Axum API + React client, PostgreSQL"
git = "https://github.com/jin3107/clean-axum.git"
branch = "template"
```

```bash
cargo generate catemplate-rust --name my-app
```

### Options

Pass them with `-d name=value`; a skipped option is asked interactively, and
Enter keeps the default.

| Option | Default | Meaning |
|---|---|---|
| `roles` | `member` | roles besides `admin`, comma separated, no spaces; at least one is needed by the tests |
| `db_host` | `localhost` | PostgreSQL host |
| `db_port` | `5432` | PostgreSQL port |
| `db_user` | `postgres` | PostgreSQL user |
| `db_name` | project name, `-` as `_` | letters, digits and `_` |

```bash
cargo generate catemplate-rust --name clinic-app -d roles=doctor,receptionist -d db_port=5433
```

### Run the generated project

```powershell
cd my-app
./scripts/new-env.ps1
cargo run
```

On Linux or macOS use `sh scripts/new-env.sh`. The script writes `.env` with a
random `JWT_SECRET` and asks for the database password.

In a second terminal:

```bash
cd my-app/client
npm install
npm run dev
```

| Address | Content |
|---|---|
| <http://localhost:5173> | web client |
| <http://localhost:3000/docs/> | Swagger UI |
| <http://localhost:3000/scalar> | Scalar |

## Work on this repository

The `main` branch is a normal project with the roles `admin`, `doctor` and
`receptionist`.

1. Copy the environment file:

   ```bash
   cp .env.example .env
   ```

2. In `.env`, set the password in `DATABASE_URL` and set `JWT_SECRET` to at least
   32 random characters. To make one:

   ```powershell
   [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
   ```

   ```bash
   openssl rand -hex 32
   ```

3. Start the API, and the client as shown above:

   ```bash
   cargo run
   ```

### Commands

| Command | Purpose |
|---|---|
| `cargo run` | start the API; migrations run at startup |
| `cargo build --release` | production build |
| `cargo test --workspace` | tests, PostgreSQL required |
| `cargo clippy --workspace --all-targets` | lint |
| `cargo fmt --all` | format |
| `cargo run --features prefork` | one worker process per core, Linux only, with `PREFORK=1` |
| `npm run dev`, `lint`, `build` (in `client/`) | client |

Tests use `TEST_DATABASE_URL`, or else the database of `DATABASE_URL` with a
`_test` suffix, which is created when missing. Test rows are left behind.

## Docker

Runs PostgreSQL, the API and the client (served by Nginx).

```bash
cp .env.docker.example .env.docker
```

Set `POSTGRES_PASSWORD` (letters and digits) and `JWT_SECRET` (at least 32 random
characters) in `.env.docker`, then:

```bash
docker compose --env-file .env.docker up -d --build
```

| Address | Content |
|---|---|
| <http://localhost:8080> | web client; `/api` is forwarded to the API |
| <http://localhost:8081/docs/> | API docs, with `APP_ENV=development` |

Both ports listen on this machine only. Behind the web service, sign-in attempts
are limited by Nginx. `docker compose --env-file .env.docker down` stops the stack;
add `-v` to delete its data as well. With Docker inside WSL, run these commands in
the Ubuntu shell. Compose does not set up Citus.

## Configuration

| Variable | Meaning |
|---|---|
| `HOST`, `PORT` | address to listen on |
| `DATABASE_URL` | PostgreSQL connection string; percent-encode special characters in the password |
| `PREFORK` | `1` with the `prefork` feature |
| `JWT_SECRET` | signing key, at least 32 characters |
| `JWT_ISSUER`, `JWT_AUDIENCE` | values that tokens must carry |
| `APP_ENV` | API docs are served only for `development` |
| `CORS_ORIGINS` | browser origins allowed to call the API, comma separated |
| `AUTH_RATE_LIMIT` | requests per minute and address for register and login; `0` turns it off |

The client's dev server forwards `/api` to `http://127.0.0.1:3000`; change
`client/vite.config.ts` if you change `PORT`.

## API

| Method and path | Access | Purpose |
|---|---|---|
| `GET /` | public | database check |
| `POST /auth/register` | public | create a tenant and its admin |
| `POST /auth/login` | public | sign in |
| `POST /auth/refresh` | refresh token | new access and refresh token |
| `POST /auth/logout` | refresh token | end the session |
| `GET /users`, `GET /users/{id}` | signed in | users of the caller's tenant |
| `POST /users` | admin | create a user |
| `GET /blogs`, `POST /blogs` | signed in | sample resource |

Access tokens last 15 minutes and refresh tokens 7 days. Send the access token as
`Authorization: Bearer <token>`; in Swagger UI press **Authorize**. Each refresh
token works once: store the new one, and send one refresh request at a time.

## Citus (optional, local development only)

For Ubuntu, including WSL. The script installs a coordinator and two workers and
**trusts every connection from 127.0.0.1**, so never use it on a server.

```bash
sudo bash deploy/citus/setup-wsl.sh
```

Set `DATABASE_URL="postgres://postgres@127.0.0.1:9700/clean_axum"`, start the app
once so that migrations run, then distribute the tables before adding data:

```bash
psql -h 127.0.0.1 -p 9700 -U postgres -d clean_axum -v ON_ERROR_STOP=1 -f deploy/citus/distribute.sql
```

Every new tenant table needs `tenant_id` in its primary key and unique indexes,
and a line in `distribute.sql`.

## Layout

| Path | Content |
|---|---|
| `api` | routers, extractors, middleware, error mapping |
| `app` | use cases, persistence, auth, sessions, config |
| `models` | entities, parameters, queries, schemas |
| `migration` | SeaORM migrations |
| `doc` | OpenAPI document |
| `utils` | database and test helpers |
| `src` | server entry point |
| `tests` | API and persistence tests |
| `client` | web client |
| `deploy/citus` | local Citus scripts |

The optional `shuttle` feature is kept from the original project and is not
tested here.

## Maintaining the template

The `template` branch holds placeholders and does not build on its own. Change code
on `main`, then merge `main` into `template`, generate a project and test it before
pushing. Do not merge `template` into `main`. Details are in `TEMPLATE.md` on that
branch.
